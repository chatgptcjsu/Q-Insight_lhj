# Q·INSIGHT 공정 품질 관리 화면 시안

## 프로젝트 개요
- **목표**: 초지 3·4·5호기의 검사성적서 데이터를 한 화면에서 확인하고, 호기별 품질 분석 시스템으로 확장합니다.
- **현재 구현**: 전체 현황, 초지345 원본 데이터 표/필터, 입력 이상 후보 검토, 호기별 검사 요약·기록, 통계표, 품명 별칭·원본 품명 표시 관리, 품질 월별 추이, 초지5 FELT 일별 운전조건 추이, 상자그림 분포 비교, 관리자 전용 일일 검사성적서 업로드·이력과 `초지345` 행 추가/갱신
- **통계표 기능**: 호기별 3·4·5호기 구분, 통계 항목 탭, 평균·σ·CPK 및 월별 값 표시, 월 열 가로 스크롤 지원
- **상자그림 기능**: `초지345` 원본의 숫자 측정값이 있는 모든 품목을 호기·월·항목별로 묶어 상자그림을 표시. 현재 파일에는 호기별 평량 10/14/13개 품목, 파열강도·인장강도도 각 동일 품목군을 포함
- **품명 관리**: 사이드바 아래쪽의 작은 관리자 버튼으로 진입합니다. `/products`는 서버의 관리자 세션을 확인하며, 호기별 표준 품명·별칭과 원본 품명 표시를 수정할 수 있습니다. 원본 이름 표시는 검사 필터·비교 및 관리 목록에 반영되지만 정적 엑셀 데이터 자체는 보존됩니다.
- **관리자 PIN**: 최초 PIN은 `0000`이며 최초 로그인 즉시 변경이 필요합니다. 새 PIN은 숫자 4~12자리이며, D1에 해시로 저장됩니다. 세션은 20분 후 만료되고, IP별 5회 실패 시 5분간 잠깁니다. PIN 복구에는 최초 발급 또는 재발급 시 한 번만 표시되는 복구 코드가 필요합니다.
- **비교 화면**: 품질 추이를 기본 탭으로 제공하며 같은 검사항목의 2~6개 품목을 월별 평균 또는 중앙값으로 비교하고 표본 수를 확인합니다. FELT 탭은 측정값을 일별로 표시하고 교체일·운휴·특기사항을 연결합니다. 기존 상자그림 분포 비교는 별도 탭으로 유지합니다.
- 품명 설정(표준 품명·별칭·원본 품명 표시)은 현재 브라우저 localStorage에 저장되어 여러 컴퓨터 사이에 공유되지 않습니다. 관리자 PIN과 인증 세션만 D1에 저장됩니다.
- **기술 상태**: Hono 기반 Cloudflare Pages/Workers 앱입니다. 관리자 인증·첨부/가져오기 이력 및 엑셀에서 읽은 최신 검사 행은 D1에, 원본 성적서는 비공개 R2 버킷에 저장합니다. 기존 JSON 원본은 기준 데이터로 유지하며 D1의 추가·갱신 행을 병합해 표시합니다.

## 화면 경로
- `/` — 초지 3·4·5호기 선택 및 전체 요약
- `/machine/3` — 초지 3호기 현황
- `/machine/4` — 초지 4호기 현황
- `/machine/5` — 초지 5호기 현황
- `/machine/:id?section=weight|burst|tensile` — 호기별 통계분석 항목 선택
- `/inspection` — 초지345 원본 표와 호기·월·품명·판정 필터, 의심값 검토
- 사이드바 하단 **관리자** 버튼 — PIN 입력 및 관리자 화면 진입
- `/products` — 관리자용 표준 품명·별칭·원본 품명 표시 관리 (유효한 서버 세션 필요)
- `/compare` — 품질 월별 추이, 초지5 FELT 일별 운전조건 추이, 상자그림 분포 비교
- `/reports` — 관리자 PIN 인증 후 검사성적서 업로드. `.xlsx/.xls`는 `초지345` 신규행 추가·동일 LOT 값 갱신, 중복/충돌 미리보기, 원본 다운로드를 지원합니다. PDF는 파일 보관만 합니다.
- `/api/reports` — 관리자 전용 첨부 이력 조회 및 엑셀 업로드/증분 반영 API
- `/api/inspection-records` — 원본 기준 데이터와 병합할 D1 추가·갱신 행
- `/api/reports/:id/download` — 관리자 전용 파일 다운로드
- `/api/reports/:id` (`DELETE`) — 관리자 전용 첨부 파일 및 이력 삭제

## 데이터 참고
- 업로드된 `2026 화장지 검사성적서` 파일의 `QLT03_New(MES전용)` 시트에서 요약·최근 기록 예시를, `통계분석 정리(초지)` 시트에서 통계표를 추출했습니다.
- 통계표에는 원본 시트의 평균, σ, CPK 및 월별 수치를 표시합니다. 원본에서 비어 있는 칸은 대시로 표시하며, 앱에서 재계산한 CPK는 아직 아닙니다.
- `초지345` 시안 데이터는 7,740개 populated rows와 44개 열을 포함합니다. 기본 표는 4,805개 식별 가능한 검사 행을 표시하고, 2,935개의 보조 계산 행도 별도 필터로 조회할 수 있습니다.
- `초지345` 시트의 검사행은 (호기, 날짜, 시, 분, LOT) 복합 키로 병합합니다. 신규 키는 추가하고, 동일 키·동일 값은 건너뛰며, 기존 키의 측정값이 달라졌으면 최신 업로드 값으로 갱신합니다. 새 파일에 없는 기존 행은 삭제하지 않습니다.
- 한 파일 안에서 동일 키의 행 값이 서로 다르거나 식별할 수 없는 행은 자동 선택하지 않고 첨부 이력의 확인/제외 수로 남깁니다. 반영된 원본 파일은 삭제할 수 없게 해 데이터 출처를 보존합니다. 재업로드는 변경이 없으면 기존 행을 다시 늘리지 않습니다.
- 초지345 원본표, 대시보드의 호기별 건수·월별 추이, 품질 추이/분포 화면은 병합된 행을 사용합니다. 호기 상세의 사전 계산 통계분석 표와 월별 상자그림 JSON은 아직 새 행을 넣어 재계산하지 않습니다.
- 이상 후보는 같은 호기·품명·검사항목 그룹의 중앙값 및 분포를 이용한 휴리스틱으로 찾으며, 원본 값을 자동 변경하지 않습니다. 현재 파일에서 6건을 후보로 찾았고, 정확한 임계값은 품질팀과 조정이 필요합니다. 확인 완료 상태는 현재 브라우저의 localStorage에만 저장됩니다.
- 요약은 초지 3호기 739건, 초지 4호기 1,643건, 초지 5호기 2,158건이며, 엑셀 판정 불합격은 초지 4호기 2건으로 확인됐습니다.
- 상자그림 비교는 현재 선택한 숫자 검사 항목·기간·호기·품목을 기준으로 재계산합니다. 표본 수가 4개 미만이면 소표본 보간값을 사용하므로 해석에 주의해야 합니다.
- 품명 별칭·신규 품목·원본 품명 표시 설정은 브라우저 localStorage에 저장됩니다. 수정한 이름 표시는 해당 브라우저에서 원본 표와 비교 목록에 사용되며, 실제 원본 JSON/엑셀 파일은 변경하지 않습니다. 관리자 PIN·세션은 D1에 저장됩니다.
- 비교 화면의 품질 기준 원본은 `inspection-data.json`이고 업로드 후 변경·추가된 행은 D1에서 가져와 함께 비교합니다. FELT 원본은 `felt-operations.json`입니다.
- FELT 워크북은 12개 교체 이력 시트와 `Felt짝` 시트로 구성됩니다. `1-2` 시트는 사용자가 기록 연도를 수정할 예정이라 현재 집계에서 제외했습니다. 나머지 11개 교체 주기에서 측정값 있는 260일을 가져왔고, 측정값 없는 예약 날짜는 제외했습니다. 일부 원본 항목은 단위가 표시되지 않아 차트에도 단위를 추정해 붙이지 않습니다.
- 자동 CPK 계산은 원시 검사 행을 초지기·품목·검사항목·규격·집계기간별로 분리하고, 제공된 Excel 규칙(이동범위, 1.128, 상·하한 규격)을 구현한 뒤 Excel 값과 대조해야 합니다. CPK 자동 계산 기능은 아직 연결되지 않았습니다.

## 개발 실행
```bash
cd /home/user/webapp
npm run db:migrate:local
npm run build
npm run preview
```

초기 진입 PIN은 `0000`입니다. 최초 로그인 직후 새 PIN으로 변경하고, 화면에 한 번 표시되는 복구 코드를 별도 장소에 안전하게 보관하세요. PIN을 잊었을 때는 관리자 창의 ‘복구 코드로 PIN 재설정’을 이용합니다. 복구 코드도 잃어버리면 D1의 관리자 인증 데이터를 관리자가 초기화해야 합니다.

## 배포 및 다음 단계
- 이 화면은 Hono/Cloudflare Pages 미리보기 템플릿에서 실행됩니다. 관리자 PIN·첨부 이력·검사행 변경분은 D1 바인딩 `DB`, 성적서 파일은 `REPORTS` R2 바인딩을 사용합니다. 로컬 미리보기 전 `npm run db:migrate:local`을 실행하고, 새 배포 환경에는 `0001`~`0004` D1 마이그레이션 및 `webapp-inspection-reports` R2 버킷을 준비해야 합니다.
- `wrangler.jsonc`의 D1 `database_id`는 로컬 개발용 예시 ID입니다. Cloudflare 배포 전 실제 D1 데이터베이스를 만들고 해당 ID로 교체해 마이그레이션을 적용해야 합니다.
- 추천 다음 단계: 기존 이력에서 '값이 수정된 동일 LOT' 항목을 확인하는 검토 화면과 통계표/상자그림 재계산 연동을 추가합니다. 운영 사이트에 적용하기 전 Cloudflare D1/R2 마이그레이션과 리소스가 준비되어야 합니다.
